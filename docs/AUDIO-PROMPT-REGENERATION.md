# 音频开场结尾与重新生成（2026-11-01）

## 结论与范围

本轮优先改进提示词，复用现有重新生成流程，不增加按钮、任务状态、自动重试、语音识别或音频合成服务。

- 删除口播中的节目分钟数和带分钟数的系列名。目标时长、字数和五段时间仍用于内容规划，明确不朗读。
- 固定开场和固定结尾提前声明为定稿原文，要求逐字朗读、不插话、前后不额外增补；书籍引入与正文另行组织。
- 归档只代表文件保存成功，不代表口播合格。试听后再决定是否用于制作成片。
- 不能承诺仅靠提示词让 NotebookLM 成品逐字一致；本轮没有真实生成、转写或试听证据。

## 当前实现依据

1. `src-tauri/src/ai/publishing.rs` 的 `AudioDraft::into_prompt` 为全量与按项调整共用的模板入口。原 `audio-template-v2` 主动把 `duration` 插入开场过渡及结尾系列名；不是下载后才改变了这些文字。
2. `src-tauri/src/audio_page.js` 的 `configureAudio` 调用 `writeAndVerify`，在提交前检查网页完整保留指导。这只能证明输入框的内容，不等于验证生成的音轨。本次用户成品未提供转写，不能据此断定其具体偏差由输入遗漏还是模型改写造成。
3. `src/modules/writing/WritingPage.vue` 在没有活动任务时允许启动，成功归档不占活动任务名额。`startAudio` 先保存当前修改，再传入已保存文案版本。
4. `src-tauri/src/database/audio.rs` 的 `start_audio_job` 新建任务并冻结提示词/来源；`complete_audio_download` 按任务 ID 生成独立文件名、追加素材。完成后可再次生成，旧文件不覆盖；未完成任务的重复启动仍返回原活动任务。

Google [Audio Overview 官方帮助](https://support.google.com/notebooklm/answer/16212820?hl=en)（2026-11-01 读取）说明：Deep Dive 为双主持人讨论，Brief 为较短的单人概览；自定义提示用于调整主题和专业程度，AI 音频可能存在错误。该页面没有承诺逐字朗读或精确分钟数。因此不把切换 Brief 作为长篇单人口播的解决方案，也不把强化提示词说成确定修复。

## 新提示词

固定开场：

> 欢迎大家收听今天的节目，我是甲子。接下来，我们一起读懂这本书。

紧接书籍引入和五部分正文，固定结尾：

> 如果你对今天的内容感兴趣，建议读一读《当前书名》这本书。
> 我是甲子。如果你喜欢这样的读书分享，记得关注我。下一期，我们继续一起读书。

`当前书名` 由程序用真实项目书名替换，不是让模型自行填空。时间与字数集中在“不朗读”的制作参数，开场结尾不随目标分钟数变化。双主持人格式下，要求同一位主讲人完整读固定段，另一位不插话；这依然是生成要求，不是网站能力保证。

版本：`audio-template-v3`、`publishing-v6`、`publishing-revision-v5`。后两者同时禁止新生成的发布/封面文案写节目时长承诺，`audio.seriesName` 固定为“读懂一本书”。旧版本文件保留用于历史追溯，运行时只使用新版本；按项调整仍不修改未选中字段。

## 试听不合格后的闭环

1. 在「音频制作」打开已归档文件，核对完整开场、完整结尾、书名和正文。不要把「音频已保存」理解为内容验收通过。
2. 直接编辑音频提示词并保存；更新后的程序也可通过「按项调整 → 音频生成提示词 → 生成预览 → 采用并保存新版本」重组指导。仅改提示词不会改变已生成音频。
3. 原任务已归档时，回到该页上方再次点击「开始生成音频」。这会新建独立任务/笔记本，并重新提交生成，可能消耗网站配额和等待时间；不是「刷新网站」「重新打开」或「继续跟进」。
4. 新成品继续追加到音频素材列表，旧成品保留。试听通过后，在发布准备明确选择本次采用的音频，并用对应音频重新制作最终视频；不自动替换已关联成片或发布任务素材。
5. 原任务只是下载/归档失败时，使用「重试下载并归档」取回原成品，不因文件保存失败重复生成。新任务失败也不影响旧音频。

复用独立任务的取舍：会重新准备来源及创建笔记本，但沿用现有明确的任务/文件关联，避免在一个已完成笔记本里新增多个音频后错误下载旧成品。本轮不新增同笔记本多成品识别逻辑。

若业务要求开场结尾百分之百一致，不应无限次重生成碰运气：在现有剪映流程使用本人录制的固定片头/片尾，剪掉生成音频的对应部分后替换。含书名的推荐句随书单独制作。这个方案把准确性从生成要求变成固定音轨，不需要书引 AI 新增服务；本轮未制作或拼接音轨。

## 生效与数据边界

- 模板通过 Rust `include_str!` 编译进应用，仓库修改不会热更新当前安装版。需要包含本轮修改的新构建，或在当前应用中手动编辑提示词。
- 已保存历史、草稿、正在执行任务的冻结输入及旧音频不批量改写。新模板只用于后续全量生成/音频按项调整。
- 无 SQL 迁移、依赖、权限、自动化状态流或下载归档逻辑变更；SQLite 仍为 v13。不改版本号、不提交、不打包或发布。
