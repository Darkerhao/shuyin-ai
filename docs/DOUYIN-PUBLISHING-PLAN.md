### B. 正常流程

```text
选好当前任务，核对文字、成片和双封面
  → 点击「开始抖音辅助发布」
  → 保存当前任务 → 执行现有检查 → 必要时生成有效任务包
  → 打开或显示官方窗口，自动识别登录状态
      未登录：显示「请扫码登录」，登录完成后自动继续
      首次使用账号：展示账号，点击一次「使用这个账号继续」
      已确认且可验证的同一账号：直接继续
  → 自动进入视频发布页，检查是否已有草稿或视频
  → 上传当前任务成片，等待平台上传及处理
  → 填入标题、发布内容和已有话题，回读
  → 设置 4:3 / 3:4 双封面，回读
  → 按当前任务选择或账号默认设置合集，回读
      首次未选择：只询问合集；可明确选择「不加入合集」
  → 显示「已准备好，请检查并发布」及逐项结果
  → 用户在官方网页检查声明、预览和发布设置，亲自发布
  → 回到应用确认实际结果，保存时间、可选作品链接和备注
  → 点击「确认记录并准备下一篇」，记录成功后开始下一任务
```

开始按钮可以串联现有保存、检查和任务包准备方法，失败就停在对应的本地问题，不发起上传。它不能替用户选择文案来源、视频、封面或勾选既有人工确认项。已有有效 ready 任务直接复用；上传时仍只消费已保存、检查通过的快照。任务包保留为内部可靠快照和可选手动交接材料，不再要求用户为正常辅助流程单独点击生成。

### C. 主界面：一个主要动作，五个可理解的步骤

上方先展示当前任务：书名、发布标题、成片文件名、双封面缩略图。其后是「抖音辅助发布」卡片，默认显示账号、目标合集和「开始抖音辅助发布」。原始 URL 和技术检查放入折叠的详情区，不作为用户必须理解的操作条件。

| 可见步骤 | 展示内容 |
| --- | --- |
| 1. 连接抖音 | 已识别账号，或正在等待扫码/账号确认 |
| 2. 上传视频 | 当前文件、平台上传进度；无真实百分比时只显示阶段 |
| 3. 填写内容 | 标题、发布内容、已有话题的实际回读结果 |
| 4. 封面与合集 | 两种封面及目标合集分别显示完成、待选择或需人工处理 |
| 5. 检查并发布 | 汇总已核对项、未完成项以及需要人工核对的声明和设置 |

进行中只保留「显示抖音窗口」和「停止并人工接管」。等待用户时，就地展示具体问题及对应动作，例如「请选择合集」，不要求先点一次通用检查按钮。普通成功进度显示在卡片内，避免连续弹出成功通知；只有完成或需要处理时给出明确提示。

准备完成后显示「查看抖音并发布」，该按钮只聚焦官方窗口。原有的独立“检查页面”“允许上传”勾选和“继续填写”按钮从主流程移除，账号确认、异常恢复均合并进同一流程。辅助流程期间继续锁定任务切换、本地文字与素材；人工接管生效后停止自动写入。

### D. 登录与页面定位

1. 保留现有独立官方 WebView 及其浏览器数据目录。等待期间由宿主定时读取页面，窗口关闭、停止或超过等待期限即结束等待；前端不再负责维持登录轮询。
2. 页面识别返回明确类别：登录页、已登录首页、空上传页、上传/处理页、视频编辑页、草稿冲突、未知页。同时识别可见账号信息、当前视频及可见阻塞提示，不只比较路径。
3. 登录成功必须有已登录区域与账号信息的正向依据。首次使用先展示昵称及页面实际公开的账号标识，由用户确认本次上传对象；后续相同且可验证的账号不重复询问。
4. 只有真实网页可读取并验证稳定的公开账号标识时，才可跨应用重启记住账号及默认合集。只有昵称时，确认范围限于当前已验证会话；重开窗口、重新登录或身份不明时再次确认，不把同名昵称当作同一账号。
5. 首页或作品管理等无未保存编辑内容的已知页面，自动导航至实测上传入口，再检查上传控件和草稿提示。编辑页、保留草稿或不明页面先判断当前内容，不强行跳转丢弃草稿。
6. 等待登录会自然继续；用户点过人工接管后，页面恢复可用也不会自行重新开始。重新继续必须由用户明确触发。

### E. 自动填入的具体内容

| 内容 | 来源与行为 |
| --- | --- |
| 视频 | 当前任务快照指定的最终成片；不重新选最近文件，不上传制作音频 |
| 标题、发布内容 | 当前任务已保存的独立快照；保留中文与换行，不临时重新生成 |
| 话题 | 只复用当前任务已有值；无话题就留空，不额外调用模型。语义话题控件的实际采用结果须单独验证 |
| 横竖封面 | 当前任务包内对应图片；等待官方页面采用并保存后回读，不把“文件已交出”当作“封面已设置” |
| 合集 | 当前任务的明确选择优先，其次是已确认账号的默认合集；均从该账号真实选项核对 |
| 章节 | 有用户明确提供、与当前成片对应的时间码和标题时才具备自动填写的前提；此次不新增音频识别或章节生成，已有手工章节始终保留 |
| 声明、可见范围、定时发布等 | 结果卡列为人工核对项，保留官方页当前设置，不根据书名或模型推测 |

当前源码未验证章节输入和时间码来源，本轮实施验收聚焦视频、文字、双封面和合集。不能以“智能填写”为由编造时间轴或承诺整套设置已经核对。

### F. 合集：首次选择，以后带入

- 首次登录后，从官方页真实合集选择器读取可用项；不从书名、系列名或 AI 输出猜合集。选择器需要在上传后才出现时，先完成上传及可确定的填写，再就地询问合集。
- 本次任务可以选择具体合集或明确「不加入合集」。选择时可勾选「记为这个账号的默认选择」，不默认替用户作此决定。
- 已保存的本次选择高于账号默认值。账号默认只作为新任务的初值，启动时记录到本次任务，后续改变默认不修改旧任务。
- 可公开读取稳定合集标识时按标识定位，并显示真实名称；没有标识时，只允许当前账号下名称完全一致且唯一的选项自动匹配。同名多项、目标消失或无法证明列表已加载时询问，不自动选择第一项。
- 切换账号立即取消原账号确认和当前自动执行许可；旧账号默认不跨账号使用。当前任务曾指定另一个账号的合集时也要重新确认目标。
- 选完等待页面选中结果并回读，不把点击下拉选项本身当成功。合集不存在、改名后无法唯一匹配或账号没有该能力时，保留已经完成的视频和文字，允许更换合集、明确不加入或转人工处理。
- 目标合集仍未核对时，状态是「等待选择/等待核对」，不能显示所有准备完成。人工完成后可明确确认本项，但界面应标明「人工确认」，不伪装成程序回读。

### G. 异常恢复：只补未完成项

| 场景 | 对应行为 |
| --- | --- |
| 同一活动会话已经上传，文字或双封面已完成一部分 | 校验原任务、账号、视频绑定及已完成项，跳过已核对且未变化的内容，只补缺项 |
| 完整封面已经由当前会话设置 | 保留封面，继续合集和最终核对，不因封面存在而拒绝整个流程 |
| 网页有另一篇或无法关联的旧草稿 | 显示「抖音有未完成草稿」，让用户先查看处理；不自动丢弃，不上传另一份视频 |
| 重启后只剩官方草稿，没有可靠任务绑定 | 先由用户核对账号和视频；不能靠标题相同推断为当前任务。核对后保留既有内容，按可证明的缺项继续 |
| 标题、简介或封面被用户手工修改 | 暂停涉及该字段的自动写入，保留网页内容；允许人工接管或明确采用网页结果，不静默覆盖 |
| 验证码或账号变化 | 暂停，在官方页处理并重新核对身份；验证码不自动处理 |
| 断网、处理中或上传响应超时 | 区分等待和失败，保留网页；恢复时先检查是否已有视频，不重发文件选择动作 |
| 合集失效或缺少入口 | 仅定位到合集问题，前面步骤保留；更换目标、明确不加入或人工处理 |
| 停止、关闭窗口或离开后再返回 | 等宿主确认停止后解除本地编辑锁；已发起的网页上传可能继续，但不再自动填写，也不自动重传 |
| 官方返回提交成功、审核中或作品链接 | 只作为待确认结果提示，沿用人工记录事务，不直接改变为 published |

恢复必须以当前会话的绑定和字段回读为依据；没有可比对的封面身份或视频身份时要求人工核对。此设计不承诺跨重启自动恢复上传进度，也不建设第二套持久化浏览器任务队列。

### H. 最小实现边界

沿用 `DouyinPublisher`，把现有活动快照扩展为一个会话：`runId`、`taskId`、当前步骤、状态、等待原因、账号绑定和字段结果。状态仅需未开始、执行中、等待用户、待检查发布、已停止、失败；步骤单独表示本地检查、连接、视频、文案、封面、合集和核对，避免为每个组合维护一套布尔值。

- **Rust 是会话状态唯一来源**：宿主持有当前会话并发出结构化事件；前端读取会话快照并订阅更新，任务 ID 和运行 ID 同时过滤旧事件。挂载和订阅重建后能重新读取当前快照。
- **一个受控执行入口**：开始命令复用现有任务校验；继续命令仅接收当前运行 ID 和限定决策，如确认账号、选合集或确认人工处理。停止后同一次运行不得再写，重试需要重新核对页面。
- **单任务串行**：重复开始只显示当前运行，不再次上传；旧的继续动作不影响新的任务。上传文件发送前保留现有任务占用，超时结果不明确时不解除占用来自动重传。
- **适配留在现有模块**：`douyin_page.js` 负责结构化只读识别；`douyin_editor.js` 负责已知页面上的有限动作与回读；`douyin.rs` 编排执行。复用 `douyin_webview.rs` 的原生文件选择，不增加 Playwright 运行时、通用 RPA 框架、视觉模型或新 Provider 空壳。
- **收敛旧入口**：把 `upload_douyin_video` 与 `complete_douyin_task` 的共同流程合并到单一执行路径，前端不再分别编排两套流程；保留现有内部校验和文件上传实现，删除被替代的手动检查/重复确认状态。

### I. 数据、迁移及影响范围

实现采用 `0011_douyin_collection.sql` 兼容迁移，持久保存用户选择的合集；下列为设计约束：

- 在 `publish_tasks` 增加一个结构化 `douyin_collection` 字段，表达未选择、明确不加入或已选目标；已选目标记录页面可得的公开账号标识、合集标识和显示名称。不能得到稳定标识时保留空值，并按上述重新确认规则执行。
- 新建任务默认为未选择；已发布历史不回填默认值。账号默认选择复用现有 `app_settings`，只按已验证的公开账号标识隔离保存，不另建账号管理模块。
- 合集是在线归类设置，独立于现有文字/素材任务包 manifest；修改合集不使已校验视频和封面包失效。启动时同时读取任务包快照与合集意图，运行中的合集选择只通过专用决策命令事务保存并更新当前会话；普通文案和素材仍锁定。
- 使用一次兼容迁移，当前基线为 schema v10；实施时按实际迁移序号追加。备份、旧备份升级恢复、任务查询及删除级联一起验证，不重写已有任务包。会话进度、Cookie 和登录凭据不入该字段或备份。
- 主要影响 `PublishingPage.vue`、`DouyinVerification.vue`、`services/douyin.ts`、`types/publishing.ts`，以及现有 Rust 抖音模块、任务查询/保存、迁移、IPC 注册/权限、备份兼容测试；不改动内容生成、音频制作或封面渲染逻辑。

本轮功能属于兼容的 `feat` / minor；多项能力同批发布只升一次，版本仍由现有发布流程处理。不改版本号、不提交、不发布。

### J. 实施顺序与验收

先在隔离的 Windows 官方窗口验证账号公开标识、登录后的真实落点、合集选择器、视频上传/处理完成标志和封面回读身份。取得真实页面证据后实现单一会话编排、合集持久化与界面收敛；最后做异常恢复、迁移和独立安装版验收。这是同一流程的实施顺序，不建设并行实现。

| 验收场景 | 通过标准 |
| --- | --- |
| 首次未登录 | 点开始后等待扫码；登录并一次确认账号后自动找发布页、上传与填写，无需再点检查和上传 |
| 同一已验证账号继续使用 | 一个开始操作连续完成；不重复扫码和逐任务勾选账号 |
| 本地任务有未保存修改 | 保存、原检查、包准备成功后才上传；任何一步失败保留修改并定位问题 |
| 已登录首页或其他已知非编辑页 | 自动进入正确上传入口，不依赖用户寻找菜单 |
| 上传与平台处理 | 分阶段展示真实状态，不伪造百分比；可播放不单独作为全部上传处理完成的证据 |
| 合集首次设置和再次使用 | 只从真实选项选择，记为默认后下个任务带入且回读一致；明确不加入也能记住 |
| 合集重名、失效、切换账号 | 不误选、不跨账号套用；仅等待解决合集问题，不重传视频 |
| 填写途中暂停并继续 | 已确认的双封面及文字保留；继续只补缺项；网页人工改动不被覆盖 |
| 旧草稿、关窗和重启 | 不清空、不重复上传；身份不明时明确确认，不用同名标题推断 |
| 停止及重复操作 | 停止确认后无新写入；重复开始及旧运行的继续动作不串任务 |
| 准备完成 | 标题、内容、双封面、合集意图均有回读或明确人工确认，声明/设置仍清楚列为人工检查 |
| 记录与下一篇 | 上传不写 published；用户确认及记录事务成功后才释放本任务并启动用户选择的下一篇 |
| 数据兼容 | 旧任务、原视频、手工章节和旧包保留；迁移、数据库/完整备份恢复通过 |

需要执行的验证：聚焦前端组件与 DOM 夹具回归、Rust 会话/并发和迁移/恢复测试，随后 lint、TypeScript、前端构建、Rust fmt/Clippy，以及隔离 Windows 真实登录/上传/合集与安装验收。夹具和历史 M6 结果不能代替本轮真实合集验收，不以用户真实发布作品作为测试前提。

## 1. 已确认的目标

用户已选择：**自动上传和填写，我检查后点一次发布**。

目标流程：选择现有发布任务 → 应用内打开抖音创作者中心 → 首次扫码登录 → 自动上传视频与封面、填写文案 → 用户检查并亲自点击抖音网页的发布按钮 → 回到书引 AI 确认结果、保存作品链接。

首轮范围是 Windows、个人单账号、同一时间一个发布任务。技术验证通过后实现完整闭环。扫码、验证码、平台声明和最终发布由用户操作；程序不代点最终发布，不读取或导出 Cookie，不读取密码，不调用逆向得到的私有接口。

## 4. 产品交互

### 发布准备页

保留素材和文案编辑区，新增一个发布操作区：

- 展示当前任务、视频名称、封面缩略图与文案预览。
- 实际入口为「打开 / 显示抖音窗口」→「检查抖音页面」→人工确认账号→「上传并自动填写当前任务」。仅操作已保存的有效 ready 任务；未保存修改先完成原有保存/任务包流程，失败时指出问题。
- 步骤提示：「等待扫码」「上传视频」「填写文案」「设置封面」「请检查并发布」。无法获得百分比时只显示步骤。
- 活动期间提供「显示发布窗口」「停止自动填写」；重复点击只聚焦现有会话，不再次上传。
- 填写完成后提示用户在抖音网页检查并发布，停止自动写入，允许用户直接修改网页内容。
- 沿用「记录发布成功」和作品链接、实际时间、备注；上传完成或审核中不自动记成功。

### 发布窗口

首版使用应用管理的独立原生子窗口，标题「抖音发布 · 书名」，内部显示官方网页。它属于书引 AI，不启动默认浏览器；二维码、上传进度、封面裁切与平台提示直接可见。

选择原因：当前 Tauri 2.12.5 同窗多 WebView 的 add_child 受 unstable 特性控制；独立 WebviewWindow 已有必要 API，可避免扩大主窗口 CSP 和改造整个布局。

登录成功以页面出现账号和上传入口为依据，不能仅凭二维码消失。开始上传前展示当前账号供核对；若网页已有其他草稿或素材，暂停让用户处理，不自动覆盖。

| 本地任务内容 | 页面处理要求 |
| --- | --- |
| 视频引用路径 | 原生浏览器接口选中当前任务的视频，等待网页确认上传及处理结果 |
| 标题、发布内容 | 按实际编辑器填写，保留中文与换行，并回读核对 |
| 可选标签 | 采用用户已有标签，适配实际话题控件；不新增话题生成能力 |
| 4:3 / 3:4 封面 | 核实页面要求后对应上传与预览，不能仅凭本地名称断言成功 |
| 可见范围、原创/AI 声明等 | 用户按内容实际情况确认，不自动猜测或勾选 |

本地业务字段不代表网页必然有相同数量的输入框。若页面共用编辑区，适配层统一组合并只填写一次。若封面比例要求不同，先确认真实要求，再调整导出或由用户在官方界面裁切，不静默拉伸。

## 5. 最小技术实现

```text
发布准备页 → 受限 Tauri Command（taskId）
  → 现有任务/素材校验，生成只读快照
  → PublishProvider 边界下的 DouyinWebPublishProvider
      → 应用自己的 WebviewWindow
      → 页面识别和文案填写脚本
      → Windows WebView2 原生文件选择
  → 步骤结果回到主窗口

用户在官方网页手动发布 → 用户确认实际成功 → 现有结果记录事务
```

一个平台保留一个实现，用少量操作表达打开、填写、读取阶段和停止。不建插件注册器、通用 RPA 框架或第二套任务系统，不增加自动点击最终发布的操作。

1. 从异步 Command 创建窗口。当前 Tauri 源码提示 Windows 同步命令内创建窗口存在死锁问题。
2. 页面读写优先使用锁定版本的 eval_with_callback，返回简短结构化结果。脚本显式捕获错误：该 API 注释提示 Windows 下异常不会自动回传为错误。仍需回读页面值验证输入确已采用。
3. 文件上传验证路线为宿主进程内 WebView2/CDP 的 DOM.setFileInputFiles；不把大视频转为 base64，不向网页开放任意文件读取，不把路径当普通 input 文本赋值。
4. 发布产品不开放远程调试端口。若 Rust COM 需要直接依赖，先核对锁文件已有版本并做可编译验证，再确定最小变更，不预先承诺零依赖。
5. 仅对实测确认的官方发布页面执行适配；顶层导航、登录回跳、新开窗口按真实官方域名核对，不泛化为任意网址。
6. 控制命令仅由可信本地主窗口调用；发布窗口不加入主窗口 capability，也不授予 remote IPC。事件只发向主窗口，主窗口 CSP 保持原边界。
7. 使用独立 WebView2 数据目录，与创作主窗口隔离。登录态不进入 SQLite、备份、任务包或日志；退出登录走官方页面，清除会话只处理专用目录。
8. Rust 只维护一个活动会话，绑定任务、快照、窗口、步骤。上传前再次校验；活动期间禁止在应用中改写该任务。人工接管后停止写入，重新填写须明确触发。

预计影响：现有发布页、publishing service/types、Rust publish commands/lib、一个集中维护的发布 Provider 模块及页面脚本、权限声明和相关测试。浏览器操作不继续放入数据库模块，具体拆文件以实际规模为准。

## 6. 状态、异常与数据

首轮无需数据库迁移，复用 schema v9：draft 表示待完善；ready 表示任务包有效；published 表示用户确认实际成功。ready 不表示上传成功，published 不能由上传回调触发。

浏览器步骤是短暂会话，Rust 维护一份、前端仅显示。重启后不承诺恢复上传进度：先查看官方网页已有草稿，检查后继续，不能自动重传或发布。

| 情况 | 处理 |
| --- | --- |
| 登录失效、验证码、风控提示 | 暂停，用户在官方页面处理，再检查状态 |
| 文件缺失、封面变化、任务更新 | 拒绝继续，保留任务，修正并重新生成包 |
| 网络失败或上传超时 | 告知具体步骤并保留网页；用户重试前先检查是否已经上传 |
| 页面变化、目标不唯一 | 停止并指出未完成项，不猜测点击位置；用户在原网页继续 |
| 停止自动填写 | 停止后续脚本；已发起的网页上传可能仍继续，取消由官方页面处理 |
| 关闭窗口或程序 | 不清空本地内容、不记成功；会话终止，不自动重启操作 |
| 页面提交成功/审核中 | 如实提示，不自动写入 published |
| 用户改动网页文案 | 不覆盖；可在结果备注说明，首轮不自动反写文案历史 |
| 识别到作品链接 | 仅预填待确认字段，不作为成功证据或静默保存 |

若以后要持久化“已提交/审核中/未通过”，另做与平台事实来源对应的兼容迁移和备份恢复验证，本轮不提前加字段。
