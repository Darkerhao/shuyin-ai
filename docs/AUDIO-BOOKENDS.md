# 音频开场引子与结尾呼应（2026-11-15）

## 需求与验收

用户确认先用本期内容引发好奇，再欢迎听众、介绍甲子；结尾回应开头的问题，再用简短固定台词告别。

- A1：整书和章节的口播顺序为本期引子、固定欢迎语、简短点题、正文、回应引子的收束、固定结束语。
- A2：引子来自本书或本章真实内容，收束回应同一看点，不编造事实或答案，不增加正文未讲的新观点、其他章节情节或下期预告。
- A3：整套生成与音频按项调整使用同一个模板；按项调整只替换选中的音频提示词。生成中预览按顺序显示引子、引入、正文指导与收束。
- A4：字幕首尾参考可以读取引子及收束，仍不能用提示词补写音频没有说出的内容。
- A5：历史提示词、已归档音频和执行中任务的冻结输入保留；无表结构、依赖、设置或自动化状态变更。

## 实现

`publishing-v10` 和 `publishing-revision-v9` 增加必填的 `hook` 与 `closing`，分别是面向听众的一句引子与1—2句收束。`introduction` 改为自我介绍后的1—2句简短点题，`sections` 继续只生成正文指导。引子最多200字、收束最多600字；缺失、空白或超长结果拒绝保存，复用原有失败保稿流程。

`AudioDraft::into_prompt` 是唯一模板组装入口，使用 `audio-template-v6`。欢迎语缩短为：

> 欢迎大家收听今天的节目，我是甲子。

固定结束语改为：

> 我是甲子，陪你读懂书里的故事，也读懂故事里的人。喜欢这期分享，记得关注，我们下期见。

`开场引子` 与 `结尾收束` 标题沿用字幕参考既有的 `开场` / `结尾` 前缀；原解析器按文档顺序合并引子和固定开场、收束和固定结尾，不把正文指导作为逐字稿，不新增解析分支。旧模板文件继续用于历史追溯，运行入口只引用当前版本。无 SQL 迁移，SQLite 仍为 v25，写入的正式业务结构仍是完整 `audioPrompt` 字符串；新增字段仅用于模型输出校验和组装，不建立重复状态。

## 生效方式与边界

模板编译进 Rust 桌面程序，需要运行包含修改的新构建。对已有书籍或章节可使用“按项调整 → 音频生成提示词 → 生成预览 → 采用并保存新版本”，后续新建音频任务使用这份已保存指导。单纯修改提示词不会改变已生成音频，运行中任务继续使用原输入。

本轮不替换正式安装版，不调用收费模型或真实 NotebookLM 生成音频；模型内容质量、外部音频是否逐字执行以及实际听感需使用新构建生成后试听。提示词要求首尾呼应，不代表已经验证真实生成结果。
