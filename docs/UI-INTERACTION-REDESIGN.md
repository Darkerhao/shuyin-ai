# 书引 AI 界面与交互改造方案

日期：2026-10-28  
状态：本轮共享视觉与交互改造完成；Tauri 桌面人工验收未执行  
适用范围：Vue 3 + Tailwind CSS 4 + shadcn-vue 的桌面工作台与窄屏布局

## 目标

让书架、内容创作、封面工坊、发布准备和设置在视觉上属于同一款书籍创作工具，并让主要操作的当前状态更容易判断。保留现有产品流程、业务文字、保存语义与安全边界；本次只调整界面结构、样式和可见的操作反馈。

## 基线观察

- 应用已经接入 shadcn-vue，现状不是缺少控件，而是应用壳层、工具条、表单和预览区视觉层级接近，主要页面有重复卡片与相似圆角边框。
- 书架无数据的桌面空状态较轻；实际书架卡片继续使用书籍封面作为视觉入口，不添加虚构的指标或宣传数据。
- 内容创作、封面与发布页面的正文/辅助文字偏小，尤其是长时间编辑时的标签和状态文字；深色品牌色目前主要停留在按钮，导航辨识度不足。
- 封面和发布表单使用粘性操作栏，长页面滚动和全页预览中操作栏会遮住部分内容或焦点，需要给滚动区留出明确空间。
- 窄屏仍保留 64px 图标侧栏，页面空间有限；导航图标需保持名称可访问，主内容优先堆叠并允许操作区换行。
- 本地浏览器访问会按产品规则禁用数据库/文件操作；视觉基线以浏览器壳层和项目既有隔离桌面截图为证据，后续交互验收使用本地测试夹具，不把夹具当成真实桌面或平台验收。

## 视觉方向

采用「阅读编辑部」方向：用清晰的编辑工作区承载长文本、封面预览和任务状态；沿用品牌深墨绿与青柠翻页色，以深色侧栏作为稳定的工作区锚点，以书籍封面作为书架的主要图像内容。内容区保持明亮、安静、易读，不做仿古纸张、装饰性渐变或每块内容都套同样卡片的 SaaS 模板。

UI 使用系统中文无衬线字体，不增加远程字体或运行时依赖；宋体只用于书籍封面标题等确有书籍语义的内容。技能检索得到的营销页结构与本产品不符，因此采用现有三步创作流程和内容优先布局；只吸收适合工作台的网格、对比度、键盘焦点和简短交互反馈建议。

### 设计复核

初次生成的参考包含营销首页的 Hero、用户评价轮播和外链字体，也推荐了偏羊皮纸与古典衬线字的组合。前者不适用于每天编辑书籍项目的桌面工具，后者容易把普通编辑控件也做成复古装饰；因此保留品牌墨绿和青柠色，以书架封面为产品视觉重点，正文与表单继续使用本机系统字体，动效维持克制。这样既保留阅读语境，也不增加网络字体依赖或宣传型 UI。

### 排版与节奏

- 工作区标题使用 28–32px、内容区标题 18–20px、正文及表单标签 14–15px、次要元信息不低于 12px。
- 书名在封面和书架实体封面中使用衬线字；控件和正文使用系统无衬线字，保持阅读与编辑任务的区分。
- 主工作区采用 8px 基础间距：页面横向留白 28–40px，面板间距 16–20px，字段间距 16px；减少仅为装饰而重复的内外边框。
- 圆角分级：控件约 8px，常规面板 12px，浮层 14px；阴影只用于浮层和明确悬浮状态。

## 页面结构

桌面端以深墨绿导航侧栏、轻量工作区顶栏和受限宽度的内容区构成固定骨架；书籍内仍沿用「内容创作 → 封面工坊 → 发布准备」的可见流程。书架保持封面网格；内容创作以分组文本编辑为主；封面页保持控制区与实时预览并排；发布页按当前任务和待完成事项组织，不改变人工确认步骤。

```text
┌────────────── 导航侧栏 ─────────────┬────────────── 工作区顶栏 ───────────────┐
│ 品牌 / 我的书籍 / 模型设置         │ 当前页面                         本地状态 │
│                                    ├─────────────────────────────────────────┤
│ 全局设置 / 关于                    │ 页面标题                         主要操作 │
│                                    │ 书籍三步流程（书籍内页面）               │
│                                    │ 内容 / 表单 / 预览                   │
└────────────────────────────────────┴─────────────────────────────────────────┘
```

```text
封面工作区：  文字、版式与背景控制     |     当前比例实时预览
编辑页：      当前编辑分组与提示       |     草稿状态和明确保存操作
发布页：      当前任务、素材与确认项   |     生成包或官方页面下一步
```

## 交互规则

1. **导航**：清楚显示当前全局页面和书籍流程步骤；保留现有可直达路由和返回书架入口。所有图标按钮都有可访问名称，窄屏不以颜色单独表示当前项。
2. **操作反馈**：沿用现有 `useOperation`、自动暂存和业务状态；长操作显示进行中状态，成功/失败使用同一套反馈位置和语气，不提前清空草稿或旧内容。
3. **编辑与保存**：脏状态清楚区分“已暂存”和“已保存为版本”。粘性操作栏只固定在滚动视口内，并为页面末端预留空间，键盘焦点不会被其遮挡。
4. **响应式**：桌面编辑/预览并排；窄屏改为纵向流程和单列面板，筛选、工具条和操作区可换行，不引入横向页面滚动。
5. **无障碍**：保留语义化标题/表单标签/ARIA 状态，统一可见 `:focus-visible`，尊重 `prefers-reduced-motion`，状态不只靠颜色表达。

- 复用现有 UI 组件、图标和系统字体；不新增依赖，不改版本，不提交或发布。

## 验收标准

- 1440px 桌面视口下导航、书架、编辑、封面预览、发布任务的层级清楚；主要正文不再依赖低对比小字。
- 1024px 与 390px 下主要区域自然折叠，无横向溢出，按钮和表单仍可操作；现有业务流程保持不变。
- 长页面滚动时保存操作不遮挡字段、预览或键盘焦点；加载、错误、已保存/未保存等状态仍可辨认。
- 键盘可访问主要导航、页签、按钮和选择控件，并能看见焦点；减少动态效果设置生效。
- 运行受影响的 Vitest、`npm run lint`、`npm run build` 和 `git diff --check`；通过浏览器截图检查桌面与窄屏布局。没有运行的桌面/外部平台验收须明确标为未覆盖。
