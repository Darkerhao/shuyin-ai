# 固定人物与精绘节奏：正式接入

日期：2026-11-17。用户批准先修正同段人物外观和短镜绘制节奏，再接入正式流程。本轮在此前自由折线功能的未提交工作上增量实施。

## 能力与取舍

新铅笔素描使用一条生成链：连续字幕规划 → 冻结角色front/side头像 → 按镜生成身体/环境/解释图 → 保存画稿 → 人工核对/单镜修订 → 同源试片/成片。

头像是任务内的数值几何，后镜只引用位置、比例、视角和镜像，不重新生成脸和帽子。同一镜头的规划角色必须完整且恰好引用一次；单镜修订保留原镜角色集合。两份front/side基准由一次规划设计，它们之间是否像同一人仍需视觉核对；本轮保证后续同视角复用相同几何，不宣称任意角度或表情自动一致。身体、手部和姿态仍由模型设计。

规划按句意分批，约48条字幕，短尾批次按时间合入或提前切点，避免49条/61条中的2秒或6.5秒尾批。每批规划后将不足12秒的短镜与相邻镜合并，保留原声时间和全部内容；整段本来短于12秒时照实际时长处理。台词继续推进时在同一场景增补已有画面，避免每句重画人物。

统一绘制器将主要轮廓按线长在字幕锚点窗口内分配，轮廓至少0.08秒；窗口容纳不了的短细线及所有排线成组渐显。笔尖只跟随主要轮廓，不追逐数百根排线。该选择以清楚观看主体成形为目标，不宣称真实铅笔的每根排线都能在24fps下逐一看到。

固定人物、短镜节奏与统一画面协议为新增兼容功能，按feat/minor判断；本轮没有手动升版、提交或推送。

## 代码与数据边界

- `src-tauri/src/video/pencil.rs`：受限路径/阴影/文字/角色结构与校验、短镜合并、批次边界、规划和逐镜生成。每次成功规划或画稿通过校验后，写回原任务再继续。
- `video_commands.rs`：新空白ink任务使用精绘生成器，带pencil的未完成任务继续原队列；保留run_id、停止选择和模型调用日志。已有折线/目录或历史图片任务仍按原记录读取；classic继续书卷分镜。
- `src-tauri/video/pencil-drawing.js`：编辑器与Frametell共用的数值编译和Canvas绘制。Frametell通过原P.tick驱动，不新增计时器或第三方绘图库。完整drawDuration与pencilCues随试片保留，角色和源码进入缓存/试片签名。
- `database/video/revision.rs`：精绘单镜候选只返回artwork，保留范围、标题、角色基准和保存原稿；候选采用仍走现有草稿与正式保存。
- `VideoDrawingPreview.vue`与视频编辑组件：精绘以同一绘制器显示完整画面，沿用原重绘、错误、等待和采用操作。用户界面不展示模型的坐标与内部绘图说明。

无新SQL表列、迁移、依赖、权限或另一套业务状态。原`video_jobs.plan_json`新增可选`pencil:{characters,pending}`，原Scene新增可选`artwork:{design,layers}`。每层包括cue、数值贝塞尔路径、遮挡、阴影、解释标签及可选头像引用。坐标画布1600×900，头像200×240。旧应用严格解析不认识这些字段，回退应使用升级前备份。

校验覆盖有限坐标、闭合区域、人物集合、字幕覆盖与锚点、每镜最多600条显式路径/6500条路径命令/60阴影区域/30标签。Rust在采用前计算展开后的笔数，JS在编译前使用同样的固定间距排线计算，包含缩放/镜像头像，整镜最多6000笔。预算超限报错并保留已保存成果，不静默删笔；普通手动调用不新增自动重试，自动任务沿用已有有限模型重试策略。

精绘单次请求上限20分钟，其他文本调用保持5分钟。超时、失败、停止和重启保留冻结头像、已完成镜头和pending，只继续缺少的画稿；修改字幕或清空分镜重建时清除旧pencil规划。单镜画面修改不改变角色基准；需要重做角色时新建任务。

## 同段真实验收

使用此前《显微镜下的大明》93.68—178.42秒、40条原字幕，未人工写逐镜构图或修改模型坐标。调用当前已启用的斑马AI / gpt-6-astra / high，使用本轮正式`pencil::generate`与原TextProvider，正式数据库仅只读选配置，任务和调用记录写隔离SQLite。

第一次规划返回了JSON，但头像mask少一层数组，严格拒绝，没有写入任务；原始输出与用量保留。明确提示词的嵌套样例后，第二次规划与5次逐镜绘图完成，规划/完成镜头逐步写回隔离任务。真实生成后还按最终校验与编译器复核，没有修坐标或使用自动纠形。

同段由7镜变成5镜，镜长约18.86、16.40、13.88、20.30、15.30秒。旧版6.52/7.12秒的短镜已合并；新版主要轮廓每镜33—60笔，细节排线成组显现。角色出现4次，两次正面和两次侧面分别复用同一份冻结几何。头像不随重绘漂移，但衣物手部造型和图解布局仍属于模型质量范畴，需要用户检查。

正式Frametell渲染85秒原声成片和30秒试片；5个相同源时间PNG完全一致，5镜回退再定位PNG相同，Engine错误0；实际主要轮廓最短时间均不小于0.08秒。编辑器真实组件在1440与390宽度显示5镜画稿，没有横向溢出或预览错误。

已保存证据：`output/pencil-integration-20261117/`。`gallery.html`提供旧/新同段同步对照；`final/video.mp4`为最终成片，`final/preview/video.mp4`为试片；`render-plan.json`、`live-plan.json`、`scratch.sqlite3`、调用回执与原始响应保留。正式库、原声文件、旧成片与安装版未改动。

### 2026-11-18 规划契约修正

《三国演义》369条字幕的新任务在第1行第2325列失败。真实模型调用已完整结束并输出11215 tokens，不是超时或截断；原始输出显示模型把输出`last`当成不含结束索引，同时每个角色对象在`heads`后漏写角色自身的`}`。`video-pencil-plan-v2`明确`last`包含该条、下一镜从`last+1`开始，并要求每个角色关闭后再写下一个；解析器只补齐`characters`数组中这种明确的缺失关闭括号，其他JSON错误仍拒绝并返回具体serde原因。

同一48条字幕批次用修正后的提示词重新调用，输出15450字节，7个角色、10镜覆盖0—47；正式`parse_manifest`、角色几何和字幕覆盖校验通过。原始输出与调用记录保存在本地忽略目录`output/model-network-20261118/`。安装版更新与桌面端续做验收不在本轮。
