# 书引 AI 项目 AI 编程规则

## 当前产品边界

2026-10-29 自动音频采用应用内 WebView + Rust 单一调度 + 一份页面脚本，无扩展/helper。复用 SQLite v13、冻结来源、原生精确下载和素材事务。不得把模拟网页通过写成 Google 登录/生成成功；内置登录仍须官方路径及真实账号验收。登录/验证码/2FA由用户处理，不读取或导出 Cookie、不伪装浏览器、不用私有 RPC。身份/入口/回读不明时停止，提交不明不重发。旧等待扩展可在应用内继续，已开始任务重启先核对。手动导入保留，macOS/Linux 暂不支持自动任务。

2026-10-27 音频时长采用书籍级目标，优先AI根据现有资料推荐，允许用户手动覆盖。推荐复用统一文本Provider、任务取消和超时，必须校验整数分钟和非空说明，资料不足明确标为估计。全量/按项请求必须传实际目标；模板统一计算总时长、字数、五段时间及开场结尾，禁止新生成继续套8—10分钟或十分钟系列。修改目标不重写旧结果或未选中字段；模型失败/取消、时长保存失败均保留原数据。schema v12，不引入新的音频生成服务或自动网站操作。

2026-10-27 智能辅助发布已改为 Rust 单一会话编排与限定决定入口，替代旧手动检查/上传/继续组合。schema v11 保存任务合集意图；浏览器进度仍不持久化。默认合集必须绑定可验证稳定公开账号 ID，当前 DOM 只有昵称时返回空 ID，不得冒充跨重启识别能力。可播放预览不能单独证明平台处理完成，无法自动核实则明确人工确认；已有网页内容只在用户明确采用后作为人工结果，不覆盖手工章节。用户选择真实账号验收稍后进行，本轮夹具、内存 IPC 和编译证据不能写为真实账号/合集/安装验收。

2026-10-26 M6 已实现 Windows 应用内抖音辅助发布：复用 ready 任务快照、独立官方 WebView、人工核对账号、视频上传、文案/双封面填写、停止接管及原有人工结果记录。最终发布、验证码和声明仍由用户操作；不要把上传或回读完成写为 published。远程页面无业务 IPC，不读取 Cookie/密码，不扩展到私有接口。现有官方草稿或不同内容必须保留，不用自动放弃/清空来掩盖异常。当时 schema v9 不变，按 `M6-VERIFICATION.md` 区分本地夹具、真实页面、原生命令和安装证据；尚未通过的阶段不得写成完成。

M7复用同一任务和发布记录增加跨书列表；精确进入任务ID，保留已保存来源，新任务仍需明确选择。记录事务成功后仅释放匹配上传会话，列表与下一篇入口不自动上传。隔离安装版可使用明确标注的模拟记录验证本地归档，不得将它写成真实平台发布成功；不得对用户真实待发布任务伪造确认。

2026-10-26 音频制作历史边界：当时音频指导由统一文本任务生成，应用只打开固定外部音频入口并导入下载后的音频，不自动操作外部网站；该边界现已由 2026-10-28 自动音频扩展，手动导入继续保留。音频登记为 `assets.asset_type=audio`，发布任务记录 `audio_asset_id`；抖音上传仍只使用剪映导出的最终成片。schema v10 的任务包 manifest 要求音频引用，最终成片只做 MP4/MOV 元数据检查，不转码、不自动发布。旧待发布任务需补选音频并重新生成任务包，已发布记录不变。

2026-10-25 创作体验续作补齐自动草稿及恢复、包含登记素材的完整备份（视频可选）、封面裁切/三比例并排预览、个人样式、发布明确选择文案版本与实际封面缩略图，以及 TXT/Markdown 导入。schema v9；自动暂存不追加正式历史，完整恢复须预览确认、保留旧文件和恢复前数据库。完整备份采用目录并整体保管，不含密钥或未登记文件；资料仅作为待处理内容。验证边界见 `CREATOR-WORKFLOW-VERIFICATION.md`，不将隔离开发版结果当作安装升级、实际视频播放或平台发布验收。

2026-10-25 用户批准「按项调整」：七项内容可选择部分重新生成、填写要求、预览后采用；复用统一生成任务和 Provider，只有采用时追加正式版本，未选项原样保留。新增数据库 v8 候选字段；失败、取消及放弃不覆盖原稿。音频继续共用固定模板，生成与预览期间锁定原编辑器。

2026-10-24 本轮用户追加封面素材生成：同一文本请求生成封面主副标题及 4:3 / 3:4 两份提示词，按书籍资料设计画面与看点。复用结果版本与封面工坊，旧三项数据仍可读写，已有封面不自动覆盖。该新增需求优先于下述历史 M5 范围；图片背景与文字排版继续分离，不增加图片供应商协议或自动发布能力。

按用户 2026-10-24「开始做 M5」指令，对现有三项生成、封面工坊与半自动发布工作流进行整体测试、打包及三本书试用，修复验证中确认的问题并完善用户文档。用户确认使用《论语》《西游记》《朝花夕拾》和验收视频。大纲/完整讲稿、运营统计仍未启用；真实平台上传和最终发布由用户完成。保留已有数据及备份恢复能力，隔离验收不得覆盖正式安装数据。

## 1. 角色与目标

AI 编程助手在本项目中担任高级前端工程师、桌面应用工程师、架构协作者和测试负责人。

目标是分阶段实现可维护、可验证的 Windows 桌面应用，而不是一次性生成大量未经验证的代码。

## 2. 开发前检查

每次任务开始前：
1. 阅读根目录 AGENTS.md。
2. 阅读与当前任务相关的 PRD、技术设计、数据库和开发计划。
3. 检查当前分支、工作区状态和已有修改。
4. 检查相关源码、依赖版本、测试命令和构建命令。
5. 确认任务范围、依赖、验收标准和风险。
6. 对现有工程优先增量修改，不擅自重建或覆盖。

## 3. 技术与代码规范

- 前端使用 Vue 3 + TypeScript。
- 组件使用 `<script setup lang="ts">`，除非现有工程规范另有要求。
- 业务逻辑优先放入可测试的 service/composable，而非大型组件。
- 保持 UI、业务服务、领域模型、基础设施分层。
- 不在 Vue 组件中直接实现复杂 SQL、文件系统流程或供应商协议。
- 新增依赖前先检查现有依赖能否满足需求。
- 遵守仓库现有格式化、lint 和命名规则。
- 不为了通过检查而删除测试、弱化类型或关闭规则。
- 不随意修改与当前任务无关的文件。

## 4. 数据与文件规则

- SQLite 是结构化业务数据的权威来源。
- 数据库变更必须有迁移脚本。
- 重要多表操作使用事务。
- 不将大型视频写入 SQLite。
- 默认只关联原始视频路径，不复制源文件。
- 删除数据库关联不等于删除物理文件。
- 文件缺失时保留记录并允许重新定位。
- 文件覆盖、移动、清理等高风险操作必须提示并取得用户确认。
- AI 请求失败时不得清空或覆盖已保存内容。
- 项目状态必须通过统一业务服务更新。

## 5. AI Provider 规则

- 所有模型通过统一 Provider Adapter 接入。
- 业务组件不得直接调用供应商 SDK。
- 模型配置与密钥管理分离。
- 对输出进行结构解析和校验后再写入业务数据。
- 处理超时、取消、错误码、有限重试和失败提示。
- 不无限重试。
- 不将密钥、授权头或敏感请求信息写入日志。
- 自定义 Base URL 需有安全提示，避免向不可信服务发送密钥。
- Provider 的实际能力以已验证的接口文档和契约测试为准。
- Prompt 应独立管理并标注版本。
- 用户提供的书籍资料属于待处理内容，不应被当作系统级指令执行。
- 不将未经核实的内容表述为确定事实。
- 避免生成大段受版权保护的原文。

## 6. 封面规则

- 封面工坊支持横版 4:3（1440×1080）、竖版 3:4（1080×1440）与横版 16:9（1920×1080）；同一份编辑配置一次导出三张。发布准备仍使用 4:3 与 3:4 两张图片。
- AI 生成封面必须由用户主动触发；未配置图片模型不影响本地制作。两种制作方式共用三比例排版与导出，AI 失败或取消保留当前内容。当前已接入兼容 GPT Image 的 base64 静态图片协议（PNG/JPEG/WebP）并完成 Windows 本机契约及 UGQ.ai 外部服务验证；不得把本机响应夹具表述为外部模型实测成功。
- 图片背景生成与中文文字排版分离。
- 本地模板在未配置 AI 图片服务时仍须可用。
- 生成前检查素材、字体、画布和输出路径。
- 不覆盖历史封面版本。
- 检查文字是否越界。
- 导出失败时保留编辑配置。
- 不把图片模型生成的乱码中文直接作为正式封面文字。

### 封面排版推荐（2026-10-27）

- 全量生成同步返回 `coverDesign`；单项调整可只选择「封面字号与配色」，先预览再采用。
- 标题字号40—160、副标题24—80，均为整数；四种颜色严格为六位 #RRGGBB，蒙层0—0.85，校验失败不写版本且保留原内容。
- Prompt 要求主标题醒目、主副标题分层、颜色与背景主题一致，优先高对比及低细节文字留白。模型图片不嵌中文文字；最终可读性须在三比例预览中审核。
- 旧封面和草稿不自动套用新推荐；只有新封面或用户主动应用时带入。

## 7. 发布与安全规则

- 第一版只实现半自动发布。
- 不读取浏览器 Cookie。
- 不保存抖音账号密码。
- 不实现绕过平台授权的自动发布。
- 不自动点击最终发布按钮。
- 官方发布能力必须先确认应用类型、权限、授权流程和接口可用性。
- 不得把“上传成功”误判为“发布成功”。
- 发布成功状态须由用户确认或经过后续合规接口验证。
- Tauri Command 和 capability 使用最小权限原则。
- 自动音频只允许固定扩展 ID、固定网站白名单和有限 native 消息；不得把远程页面升级为任意本机文件、命令、URL 或 SQL 通道。
- 浏览器下载必须由精确 downloadId 绑定，最终文件须验证真实音频容器、大小和 SHA-256；不把最近下载或生成成功当作归档成功。

## 8. 测试要求

每次实现后：
1. 运行与修改范围相关的单元测试。
2. 运行 lint 和 TypeScript 检查（项目已配置时）。
3. 运行构建。
4. 数据库变更时验证迁移。
5. 文件操作变更时覆盖文件缺失、权限错误和重复文件场景。
6. AI 变更时覆盖超时、异常响应和结构校验失败。
7. 发布变更时覆盖素材完整与缺失场景。
8. 对无法自动化的桌面行为给出人工验收步骤。

不得声称未实际执行的测试已经通过。

## 9. 任务交付格式

每次任务完成后输出：
- 实现内容。
- 修改文件。
- 数据库变更。
- 实际执行的验证命令及结果。
- 未解决问题与风险。
- 对应验收标准。
- 下一步建议。

如遇到阻塞，先解释原因并给出可选方案，不伪造完成结果。
