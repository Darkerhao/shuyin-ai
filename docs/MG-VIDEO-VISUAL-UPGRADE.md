# 原声读书视频：画面内容扩展与质感升级方案

初稿日期：2026-11-01。2026-11-02状态：P0已实施；用户随后确认P1，6场景/三景别/8项物体已接入并验证，P2仍待单独确认。初稿基线`d4a9dac`，P0基线`046f054`/v0.31.0，P1基线`0e86f39`/v0.32.1；不手动升版本。

本文保留原方案动机与后置取舍。P0交付导演校对、动作时机和同源试片，见 [P0验收](VIDEO-DIRECTOR-VERIFICATION.md)；P1实际采用6类轻场景、三景别和8项字幕缺口物体，见 [P1验收](VIDEO-SCENES-VERIFICATION.md)。24候选并未全部采用，美学评分、三类内容听审、长片和P2图片仍不能当作已验收能力。

## 1. 直接结论

**可以接入更多画面内容，但最值得做的不是把85种物体扩成几百个图标，而是让现有物体形成有场景、有主次、有情绪、有前后联系的画面。**

推荐沿用现有书卷手绘，升级为「书卷式叙事影像」：

> 克制的场景底图 + 清楚的主体物体 + 有含义的动作 + 舒缓的景别变化 + 少量关键插画。

保持一个渲染流程，不换引擎、不重配原声、不把视频做成会动的PPT，也不靠黑金配色、粒子、转场或4K标签制造“高级感”。

优先顺序：

1. **先让镜头会讲故事**：修正物体与动作的时机表达，控制重复、主次和停留，让观众看见旁白正在讲什么。
2. **再增加画面层次**：先做6类轻场景、远中近景别和一批真正缺少的高频物体，不扩大全部镜头的信息密度。
3. **最后增加少量精制插画/资料画面**：放在开场、章节转折和结尾，而不是每句旁白都生成一张图。

判断标准不是“用了多少素材”，而是：**画面是否更贴题、更容易理解、更有变化，同时仍然统一、耐看。**

## 2. 当前能力与实际限制

以下为方案初稿时`d4a9dac`源码基线，而不是根据项目简介推测；P0已调整其中的主次、动作时机、预览和编辑能力，当前实现以验收文档为准。

| 项目 | 当前实际实现 | 对优化的意义 |
| --- | --- | --- |
| 物体/构图/动作 | 唯一目录包含85个物体键、13个构图键、6个动作键 | 已经有可复用底座，不需要另接一套图标系统 |
| 单镜容量 | 最多16条字幕、1—3个beat；标题20字、标签8字 | “更多内容”应扩展可选内容，不是把每镜塞进更多东西 |
| 构图差异 | 绘制主体主要使用三组`places`；其余差异来自连线、方向、强调和语义 | 13类构图不等于13套完全不同的空间布局，继续增加kind名称未必改善观感 |
| 动作锚点 | 首物体从页内`-0.6`秒预绘；其余取字幕起点；移动通常从`at + 1.3`推进，勾/叉从`at + 2.7`出现 | 已有字幕驱动，但不能声称所有动作都在锚点句首精准发生 |
| 物体身份 | 一个beat创建一个绘图实例，没有同一物体的多事件时间线 | 重复输出同名物体可能画出两个物体，不等于让同一个物体再次行动 |
| 分镜上下文 | 每批24条字幕，附首尾各最多6条、最近3镜、后续3条 | 已有局部连续性设计；优化应加强使用与检查，不重复建设 |
| 字幕精度 | 转写内部使用词级时间戳，但输出/保存为句级`start/end/text` | 现阶段不能实现可信的逐词高亮或词级物体触发 |
| 图片能力 | 已有静态PNG/JPEG/WebP的ImageProvider和图片素材；生成任务仍为封面用途 | 可复用Provider与图片校验，但视频分镜尚不能直接引用图片 |
| 渲染与缓存 | 单一可信绘图；缓存键包含整份plan、编译器、绘图、目录及引擎路径 | 同输入可重试复用；目前不能承诺“只改一镜就只渲染一镜” |

## 3. 还能增加哪些画面内容

### 3.1 第一优先：从孤立物体变成轻场景

增加以下6类场景预设。它们是同一绘图中的背景层和摆位规则，不是6个新的渲染器。

P1实现采用下表的空间意图，但背景只画桌面、门墙、街区、山岸、窗框、地形轮廓；书、灯、桥、椅子或人物不会自动放入背景，需叙事时必须作为beats选用。这样既形成层次，也不绕开主体容量或提前透露台词。

| 场景 | 画面组成 | 适用内容 | 控制原则 |
| --- | --- | --- | --- |
| 书房案头 `study` | 桌面、书、灯、窗框轮廓 | 阅读、思考、写作、回忆 | 装饰不添加新的事实，不堆满书架细节 |
| 庭院门墙 `courtyard` | 宫门/墙体局部、地面、远近关系 | 历史、身份、进入/离开、内外对照 | 不把示意建筑标成具体历史建筑复原 |
| 城市街道 `street` | 建筑剪影、道路、一个主体 | 社会生活、职业、迁移 | 背景不与主要动作同时抢注意力 |
| 河岸远山 `riverbank` | 河流、桥梁、远山轮廓 | 时间流逝、人生转折、连接 | 不添加未经核实的地理名称 |
| 窗边独处 `window` | 窗框、光影块、椅子/人物 | 孤独、选择、内心冲突 | 不靠持续下雨、飘叶或闪光填充时间 |
| 路径地形 `path` | 路径、岔路、阶梯/远处目标 | 成长、决策、阶段推进 | 延续当前route语义，不再维护第二套路径绘图 |

保留现有空纸背景`plain`。抽象解释、重要对比或素材不适配时，直接使用干净背景，不强行加入环境。

场景最多承担“在哪里、什么氛围”两件事；主体物体承担“发生什么”。背景装饰不计入3个叙事主体，但任何需要观众理解的对象必须计入，不能借背景绕过容量限制。

### 3.2 第二优先：补高频缺口，而不是无限扩库

建议先建立以下24项候选，全部通过同一目录和`sketch`绘制入口接入；若全部采用，85项变为109项。数量不是验收目标，应先用真实书籍字幕验证缺口，再决定本批实际采用哪些。

本批已采用8项：`brain/compass/road_fork/mountain/tree/window/cup/bed`，总数93。依据为既有《我的前半生》《人生由我》和睡眠/咖啡知识样片的真实字幕：指南针、大脑、杯子为直接物体，选择/休息/山地/树木/光照需要相应可辨认画面。其余16项暂缓，不假称本轮已扩至109项；实际试听与模型内容选择仍单独验收。

| 类别 | 候选物体及拟用键 | 主要用途 |
| --- | --- | --- |
| 认知与学习 | 大脑 `brain`、灯泡 `lightbulb`、拼图 `puzzle`、齿轮 `gear` | 理解、启发、组合、机制 |
| 方向与选择 | 指南针 `compass`、岔路 `road_fork`、山峰 `mountain`、灯塔 `lighthouse` | 方向、抉择、目标、引导 |
| 成长与积累 | 种子 `seed`、幼苗 `sapling`、树木 `tree`、树根 `roots` | 起点、成长、积累、根基 |
| 情绪与能量 | 电池 `battery`、绳结 `knot`、雨伞 `umbrella`、气球 `balloon` | 消耗、纠结、庇护、放手 |
| 日常与空间 | 窗户 `window`、台灯 `desk_lamp`、杯子 `cup`、床 `bed` | 日常场景、专注、休息 |
| 关系与机制 | 磁铁 `magnet`、关系网 `network`、多米诺骨牌 `domino`、漏斗 `funnel` | 吸引、联系、连锁反应、筛选 |

每个对象至少要求：小尺寸可辨认、与现有线条/填色一致、具有安全边界、可确定性重绘、动作适用。`seed`和`tree`是两个物体；**在没有专门实现前，不把两者切换宣传为连续生长动画。**

皇冠、书本、天平、地图、人物、时钟等已经存在，不再换名字重复添加。暂不引入在线素材商店、向量检索、任意SVG上传或模型生成绘图代码。

### 3.3 第三优先：让画面承载关系与证据

| 内容 | 推荐做法 | 边界 |
| --- | --- | --- |
| 人物关系 | 少量剪影、稳定短标签、关系线 | 不凭空生成人脸，不把所有角色画成需要猜测身份的小人 |
| 因果/过程 | 具体物体构成2—3步变化，箭头表示真实关系 | 不是重新启用纯文字流程卡；没有旁白依据的因果关系不画 |
| 时间与空间 | 以现有日历、时钟、地图、路径为底座 | 精确时间线、地名、路线和边界需要可核验的数据，不由模型补齐 |
| 原书与史料 | 用户已提供且有权使用的封面、少量书页、照片、信件局部 | 显示来源；不自动扫描/解析整本PDF，不生成伪造档案或大段原文 |
| 关键插画 | 一张构图好的静态插画，叠加少量可信线条或轻推近 | 用于情绪节点；不让图片模型绘制正式中文字幕 |
| 真实辅助镜头 | 用户自有/有明确授权的翻书、写字、街景片段 | 后置；需要片段区间、裁切、帧率及音轨处理，不是直接把MP4当图片 |

**优先接静态插画和用户已有图片，不优先接通用AI视频生成。** 静态素材更容易保持风格、确认内容、缓存和重做；AI视频还带来人物漂移、物体变形、时间匹配、费用和外部等待等额外成本。

## 4. “更高级”具体怎样落到画面上

### 4.1 一套视觉语言，不是每本书换一套皮肤

延续当前纸张和手绘，主方向是干净的出版物插画，而不是儿童贴纸或炫技演示。

- **配色**：纸白/暖灰做底，墨色做主体，墨绿与赭色按语义强调。保留有含义的红/蓝，但一镜不同时强调所有颜色。
- **层次**：背景低对比、主体清晰、标签其次、字幕独立。先看主体，再看关系，最后读短标签。
- **线条**：统一粗细和手绘扰动；新增物体不混入写实照片边缘、粗黑表情包或高饱和扁平图标。
- **字体**：复用现有可分发字体。标题、物体标签和字幕分层，不新增网络字体，不把每句话都做大字标题。
- **留白**：优先减少重复标题和装饰，让主体更大，而不是把空白全部填满。
- **系列识别**：保持书名/系列标识，但减弱每镜重复的顶栏、横线与页码，不与核心画面竞争。

现有纸纹已经存在。先校正对比度和细节密度，不再叠一层噪声、光斑或动态粒子。

### 4.2 景别变化比更多转场更有价值

在同一绘图中增加三种有实际区别的景别：

| 景别 | 画面职责 | 示例 |
| --- | --- | --- |
| 远景 `wide` | 交代环境和空间关系 | 人物位于门墙之间、走向一条路 |
| 中景 `medium` | 讲清一个动作或两者关系 | 人物与契约、书本与钢笔 |
| 特写 `detail` | 让注意力落到一个重要对象 | 钥匙、封印、指南针、信件局部 |

同时保留`reference`表示当前既有摆位，供旧分镜读取和新片有意复用；全部走同一绘制函数，不复制旧模板。

镜头默认静止，远/中/近通过主体尺寸和构图实现，不依赖大倍率缩放。P1落定为仅`kind=focus + framing=detail`且首beat后至少3秒时，从该cue起点轻推近一次（1.06倍、3秒）；其他组合不移动，不增加平移参数。原先1.05—1.08倍/2—4秒只是调试区间，不代表额外可编辑选项。

本机锁定引擎0.7.3已有`cam(keys)`及独立`hud`层，已核对`runtime/core.js`与`runtime/engine.js`实际实现。P1使用受控关键帧，把标题、系列标识、页号和进度移到HUD；字幕继续使用引擎独立字幕层。不改第三方源码，不套用引擎默认0.28秒、1.25倍的快速`push`。

所有运动必须由绝对时间计算，前后拖动到同一时间得到同一画面；不使用系统时间、未固定的随机数或无法精确定位的循环CSS动画。

### 4.3 动作要表达事情，而不是证明“画面在动”

继续用现有6种动作打磨语义：倾斜表示失衡，移动表示迁移，勾叉表示确认/否定。不是每个物体都必须动，也不是每句旁白都必须出现新物体。

“开门、断链、点亮、生长、翻页”等确实能增加表现力，但应在真实分镜需要时逐项增加受控实现，并限定适用物体；不能给所有物体套同一个缩放动画后声称支持这些动作。

首期不增加同一物体的多事件编辑器。若后续确实需要“钥匙先出现、后来移动、最后开锁”，再引入明确的物体实例和事件引用，替换现有一beat一实例的限制；不要用重复beat假装已经实现。

## 5. 分镜模型怎样变得更像导演

### 5.1 先加强已有信息的使用

模型已经输出具体物体、动作与字幕锚点，下一步要约束的是选择质量：

1. **先理解这一镜的用途**：交代、对比、转折或收束，再选物体，不逐个把名词换成图标。
2. **一镜一个视觉中心**：其他对象解释它，不争抢相同大小和相同强调色。
3. **前后保持联系**：同一概念尽量保持同一物体和标签；主题物体可以反复出现，但应有叙事进展，而不是随机换物。
4. **按观点分镜**：批次边界不是语义边界，24条上限内优先在完整句意处切分，继续保留连续覆盖与有界请求。
5. **控制变化与停留**：复杂解释允许停留；只有新的信息到来才增加动作。3—6秒推进可作参考，不能机械补动画。
6. **最后做全片轻量检查**：提示连续重复的构图、空泛物体、过密锚点和不合理长停留，不另建多模型“导演委员会”。

结构违法、时间越界、缺素材必须阻止渲染；“是否太单调”等审美规则只给出可定位的提醒，由用户确认，不无限重试模型，也不自动替换已确认镜头。

### 5.2 把预绘与真正的语义动作分开

现有第一物体提前绘制是为了开场不空白，但若它承载后半句才出现的结果，会提前泄露信息；勾叉固定延后2.7秒也可能错过所指台词。

推荐统一规则：

- 场景底图可以预先出现，不能提前显示结论、否定符号或关键结果。
- 主体的入场/绘制由该beat的`cue`决定；需要开镜就存在的主体，明确把锚点设为本镜第一条。
- 语义动作的开始以锚点为准，绘制过程和动作持续时间由可信实现控制，不能把所有动作都固定延后同一个秒数。
- 第一条字幕前的自然静音可展示书名和非结论性底图，不改原声或补造台词。
- 同一时刻允许有必要的并列比较；过密但合法的动作先提醒，不通过篡改字幕时间“修好”。

上述时间语义已在P0实施，P1继续保留；首物体不再预绘，场景结构层可预先存在，不提前画叙事结论。

### 5.3 最小契约演进

首期场景/景别只需在现有Scene上增加两个受控字段，不引入任意坐标、镜头轨迹、图片URL或代码：

- `environment`：`plain/study/courtyard/street/riverbank/window/path`。
- `framing`：`reference/wide/medium/detail`。

下面是**P1已支持的单镜契约示例**，不是用户原书字幕或已经生成的分镜；`compass`、`road_fork`已进入93项目录。

```json
{
  "first": 0,
  "last": 2,
  "kind": "route",
  "title": "寻找自己的方向",
  "environment": "path",
  "framing": "wide",
  "beats": [
    { "cue": 0, "object": "person", "action": "draw", "label": "自己" },
    { "cue": 1, "object": "compass", "action": "draw", "label": "方向" },
    { "cue": 2, "object": "road_fork", "action": "slide", "label": "选择" }
  ]
}
```

`kind`继续表示既有叙事构图，`environment`只负责底图，`framing`只负责取景。选择规则由同一目录与绘制层统一维护，组合必须满足边界检查，不能只让前端下拉框支持。

现有Rust使用`deny_unknown_fields`，因此需要同步Rust类型/校验、Node编译、Vue类型/编辑器和版本化Prompt。新程序读取未包含新字段的旧物体分镜时，按`plain + reference`解释，不重写历史JSON；旧文字卡分镜继续沿用现有明确升级入口，不恢复旧渲染器。

P1已将唯一Prompt升级为`video-storyboard-v4`并同步上述字段，v3不再保留生成入口；Prompt版本不等于持久化schema版本。P1字段继续保存在`plan_json`，SQLite仍v14，没有新增表或通用工作流；旧应用不保证读懂新字段，回退程序需保留升级前备份。

### 5.4 关键词级同步放在后续

先把句级触发做好。需要“说到某个词才点亮”时，必须保留真实测得的词级对齐或重新对齐，不能按字数平分字幕时长。

仅有SRT的任务继续明确使用句级精度；用户校对文字后，原词级对齐不一定有效，须重新核对，不能静默沿用。两种输入精度最终进入同一时间计算流程，不建立两套渲染器。

## 6. 一个30秒画面示意

以下是虚构的表达示例，不是原书引文、现有字幕或已生成影片。时间仅帮助理解；实际镜头边界必须从用户原声SRT读取。

| 示例时段 | 假设旁白主题 | 画面 | 比现在更好的地方 |
| --- | --- | --- | --- |
| 0—8秒 | 走得快不等于方向正确 | 岔路远景中一个人物，路径缓慢显现 | 有环境和问题，不是先放一张书本图标 |
| 8—16秒 | 先辨认自己的方向 | 指南针成为中景主体，岔路弱化 | 视线有明确落点，不同时展示三个同权重物体 |
| 16—24秒 | 再选择具体的一步 | 人物与现有阶梯形成推进关系 | 复用前镜主题，动作由这句原声触发 |
| 24—30秒 | 回到当下的行动 | 桌上的书与钢笔，短暂停留后收束 | 形成首尾意义联系，而不是结束在居中金句卡 |

这个示例最需要的是**场景、主次、时间与连续性**，不是新增几十个特效。新版是否真的更好，仍需与同一原声的旧版并排观看。

## 7. 图片/插画怎样接入，才不增加一堆复杂度

### 7.1 第一批只接已确认的静态图片

沿用现有`assets`，新增分镜图片引用时只接受本书已登记的`assetId`。不允许模型输出任意本地路径或网络URL，不让渲染过程联网找图。

闭环应是：

```text
用户导入/选用本书图片
  -> 校验静态格式、尺寸、大小与使用权信息
  -> 分镜引用素材ID并确认裁切
  -> 宿主解析、冻结图片摘要及本次使用信息
  -> 同一个渲染工程中的受控图片层
  -> 成片检查、登记及原有发布选择
```

图片需在页面就绪前完成加载和解码，缺失即停止，不以空白占位继续编码。源摘要、裁切和样式参与缓存键；用户后来更改源图片时，不复用旧缓存冒充新结果。

当前书引没有视频图片层，不能只改Prompt就实现。实施这一阶段时先验证锁定引擎内的受限本地图片合成、定位确定性和中文路径，再接UI与任务；不假设存在未经核对的`P.image`接口，不为图片另开第二个渲染流程。

### 7.2 AI插画复用Provider，不借封面任务冒名生成

静态图片闭环验收后，再允许用户主动为少量关键镜头生成插画：

- 复用已有ImageProvider、凭据和图片解码，不新增图片供应商SDK。
- 使用独立版本化“视频插画”Prompt，画面风格、主体比例、字幕留白保持一致；不能直接拿封面Prompt批量生成。
- 不把视频插画任务写成`kind=cover`。当前任务种类/约束需在实施时核对，必要的用途扩展必须配套迁移和恢复测试。
- 建议试点每10分钟片子先控制在4—6张独立插画，用在关键节点；这是费用控制起点，不是按时长强制生成的配额。
- 生成前显示张数、模型和是否上传素材；未经确认不发请求，不承诺未查询的价格。失败后保留已采用图片和原分镜，不自动无限补图。
- 图片中的中文统一由可信排版层绘制，不直接使用图片模型生成的乱码字。

同一人脸、场景跨多张图的一致性不能靠Prompt保证。首批优先环境、物件和匿名人物剪影，不承诺真实人物复原。

### 7.3 来源、版权与数据归属

“网上能下载”“老照片”“模型生成”都不自动等于允许商用。图片需要记录来源、创作者/权利人（已知时）、授权说明或用户自有声明；未提供的作者不代填。

当前assets没有这些字段。第一批可把**本次使用**的素材ID、来源/授权说明、裁切和摘要存入视频计划快照，随SQLite备份；这不是第二套资产主档。若后续要跨项目管理授权，再单独论证数据模型，不预建素材平台。

书页/照片等原文件默认只关联；渲染所需派生副本写本任务目录，不覆盖原件。备份仍走已有素材收集规则，并测试计划中的图片引用、恢复和缺失提示。正式分发仍需核对引擎AGPL、字体与素材许可；本方案不改变现有独立引擎分发边界。

## 8. 还值得同步优化的体验与工程问题

### 8.1 先看画面，再花时间跑整片

在现有视频制作页增加分镜缩略图、对应字幕和风险提醒，复用当前编辑/确认入口，不另做剪辑软件式时间线。

推荐流程：`准备字幕与分镜 -> 看缩略图/选一个30—60秒片段试渲染 -> 调整并保存 -> 确认整片 -> 播放/选用发布`。

缩略图和试片必须来自同一渲染器，不在Vue中重画一套“看起来差不多”的预览。试片是派生预览，不得登记为正式成功成片、自动选用于发布或解锁整片成功状态。

P0已经显式实现片段模式：保留原plan及全局cue索引，只在派生渲染视图中使用`片段时间 = 原声时间 - 片段起点`，同时截取对应原声，不重做ASR、不改写SRT、不绕过原声时长校验。P1的背景/景别/镜头继续共享原scene时钟，末镜截短也不加快绘制或推近。

### 8.2 声音质量影响“高级感”，但不能悄悄改原声

保持原声、原速、原时间轴和现有响度处理边界。可先增加只读响度/峰值提醒；只有用户明确启用声音处理后，才讨论响度统一、轻降噪或低音量配乐，并生成新输出。

不默认加背景音乐、不自动删停顿、不压缩音频来配画面。配乐与拟音是后置项：需要授权、混音和试听，不能为了热闹盖住读书内容。当前MP4合入AAC并不等于源音频字节复制，但源文件仍必须不变。

### 8.3 清晰、稳定、可恢复，比先上4K/60fps更重要

继续以1920×1080、24fps验证，先保证文字清晰、细线不闪、动作不抖、没有压缩脏边。高分辨率和高帧率不能修正空洞分镜，还会增加渲染时间和文件大小。

- 新场景限制图层/路径数量，图片加载后复用，不每帧解码。
- 真实耗时、内存和磁盘占用用同机器、同原声对比，区分冷渲染与缓存重试，不提前承诺提速百分比。
- 继续保留严格布局/确定性检查、停止进程树、失败保稿和旧作品，不用提高阈值掩盖新镜头问题。
- 同输入重试沿用既有缓存；镜头级缓存优化后置，不能把当前整plan缓存说成局部增量渲染。
- 竖屏是后续独立版式，不直接裁切横屏；字幕安全区需按最终目标平台另验，不与这轮扩库混做。

## 10. 怎样验收“真的更好看”

以下为后续验收方案，不是本轮测试结果。

### 10.1 技术硬门槛

| 检查 | 建议通过条件 |
| --- | --- |
| 分镜与时间 | 字幕连续覆盖、合法枚举、锚点范围和顺序全部通过；绝不改原音频时间来迎合画面 |
| 语义动作起点 | 对已确认句级cue的计划起点，首个可见变化落在不超过1帧的量化范围内；不把它当作ASR或词级识别精度承诺 |
| 画面安全 | 标题、主体、标签和字幕在各景别及运动极值处无裁切、碰撞；新增图片全部解码成功 |
| 可复现性 | 同一时间从前/后跳转、重复渲染一致；保留现有严格检查，不以修改预期哈希代替画面验收 |
| 数据与权限 | 原音频/旧MP4/SRT不变；跨书素材拒绝；未知字段/非法路径拒绝；失败不清空计划 |
| 工作流 | 预览不登记为正式成片；停止/重启可恢复；最终MP4/SRT事务唯一登记；发布必须明确选用 |

改动旧85物体绘图时必须有逐对象或画面基准对照；新增对象也必须进入完整枚举、有限数值、边界与确定性检查，不能只增加目录计数。

### 10.2 美学与理解验收

选择历史传记、成长心理、知识解释三类真实内容，各取60—90秒有代表性的原声，覆盖开场、解释、转折和收束；再至少完成一条原长度长片，检查风格疲劳和性能。

新旧版使用同一音频、字幕、输出规格，优先先对比分镜，再逐步加入新资产，避免所有参数一起改而无法判断收益。

建议由用户和两位观看者分别对“贴题、易懂、统一、节奏、耐看”打1—5分；新版各维度目标至少4分、三人中至少两人偏好新版。样本很小，只能作为内部试片判断，不能宣称提高平台完播率。

可定位的提醒包括：连续三镜同构图/同主体而没有语义进展、短时间挤入多个动作、长段落没有有效视觉变化、背景比主体更醒目。主题物体的有意回扣、自然停顿和复杂解释允许人工保留，不为刷指标随机换图。

人工必须实际播放并试听，不能只看联系表截图；同时检查末句、静音间隙、字幕断句、图片事实和来源。真实模型输出也要单独验收，本地契约夹具不代表AI会稳定选出好分镜。
